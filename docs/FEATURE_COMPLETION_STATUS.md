# Feature checklist status

This is an implementation audit of the supplied product list. “Implemented” means there is application code; it does not mean a production provider has been configured or tested. Recheck this file as integrations are added.

## Update, 24 November 2026

- **Voice answers:** the system prompt was rewritten and cut from about 2,300–2,900 tokens to about 750–890 (answer only what was asked, only company-knowledge facts, one or two sentences, no repeated filler, honest about transfers, simple spoken Hindi, real Hinglish with English product words). Each turn's note now carries today's date and time in India and the caller's name exactly as first heard. `PROMPT_VERSION=legacy` brings the old prompt back for comparisons.
- **Booking a callback or demo** is now a state machine (`apps/voice/src/booking.ts`), not free chat: name, then day, then time, one question at a time; "today / आज / aaj", "tomorrow / कल / kal", weekdays and "24 November" resolved in India time; a weekday that disagrees with the date is asked about once; Hindi and Hinglish times ("दोपहर एक बजे", "1 baje", "साढ़े चार", "एक बज़ेट" slip); a time already passed today is refused; one confirmation line, then it stops asking; a later change updates it. Bookings are saved (`call_bookings`, migration 0049), the lead is marked callback requested, admins and managers are e-mailed, and they show on Call logs. "Thank you / धन्यवाद / take care" gets one short goodbye.
- **Latency figures** are now measured from the same two moments for every turn: when the caller stopped speaking (a new end-of-speech signal from the local recogniser) and when the transcript arrived. The Live page shows each stage and labels answers from the model, saved answers and fixed lines, so a near-zero stage is understood (it was the "Voice starts 0 ms" confusion).
- **KYC:** PAN and GSTIN can be checked against the government records through Cashfree Verification (`KYC_PROVIDER=cashfree`, `CASHFREE_CLIENT_ID/SECRET`). A PAN that is not valid or a GSTIN that is cancelled/suspended is refused on submit; the name on record and the match score are shown to the reviewer; when the service is down the request goes through marked "could not be checked". Written from Cashfree's documented API and tested against mocked answers only (no Cashfree account here).
- **Provider keys in the website** (Platform > Provider keys, staff only, password re-check): Twilio/Plivo, the six payment gateways, OpenRouter/Deepgram/ElevenLabs, KYC and SMTP keys are stored encrypted (AES-256-GCM, migration 0051), never shown again (last four characters only), override the env file, and reach the web app at once and the voice service and worker within a minute.
- **Two-way CRM sync:** the CRM can send contacts in (`POST /api/integrations/inbound`, API token with leads.write, up to 500 per request): created or updated by phone, status changes recorded, refused rows reported, each batch logged and shown on the Integrations page, and nothing echoed back to the CRM (migration 0052). **Integration health test:** one button runs five checks (switched on, public HTTPS address, signed request accepted and how fast, 24-hour failure rate, last delivery) and saves an ok/degraded/down verdict.
- **Team management** (add a person, change a role, switch off/on, audited), **organisation settings save only with the admin's password**, **Delete for cloned voices**, and fixes to the Integrations crash and the theme-builder Save.
- **Tests:** 490 unit tests and 101 database integration tests (against a local test database with row-level security) pass. Live measurements are in the report of 24 November 2026.

## Implemented in the current application

- Local live voice conversation, streaming transcript/partials, turn handling, interruption support, knowledge-grounded answers, transfer flow, call recording/transcription, post-call sentiment and lead analysis.
- AskG1 plus a configurable OpenRouter model choice; the server offers the requested model IDs as examples. Provider availability and quality depend on credentials and service health.
- Campaigns can select an organisation-owned agent profile with its own instructions and knowledge text, or inherit organisation settings. Profiles are reusable and template selections are preserved. Campaigns can also override the organisation's model with AskG1 or a validated OpenRouter model ID.
- Knowledge ingestion and search, agent/Studio voice workflows, Plivo call/signature/DTMF/AMD handling, scheduled AI/audio campaigns, reusable saved campaign settings, retries, concurrency, pause/resume/cancel, variants and campaign queue counts.
- SMS bulk and individual queues, saved templates, inbound Plivo SMS, opt-out handling, knowledge-based automatic replies, message statuses, tagged audiences, and multi-step sequences with bulk and individual enrollment.
- Contacts with CSV import/export progress, tags, custom fields, scopes, history, lead scoring, and Leads-page search/status/score/tag/consent/DND filters with a scoped result count. Individual SMS and full per-lead SMS history are available from the lead page.
- Call/report dashboards, webhook integrations and delivery history, KYC workflow, number request/approval inventory, billing ledger, the six listed payment-provider adapters, exchange-rate support and profit reporting.
- TOTP MFA, scoped roles/permissions, tenant-scoped database access, self-service expiring API tokens with permission scopes and immediate revocation, audit records, rate-limit helpers, secure password hashing (Argon2id), administrative controls, and a website widget.
- **Permanent cloned voices (Karan, Naveen, Suhani):** these are self-hosted Pocket TTS clones. The real voice lives in `.local/voices/<providerVoiceId>.*` (gitignored; back it up). `packages/db/cloned-voices.json` lists them and `seed-demo.ts` re-registers their profiles, consent links and kept recordings on every run of `dev-db.sh`, which drops and rebuilds the whole dev database. Cloning someone new in the UI only creates a database row, so add them to `cloned-voices.json` to make them survive a rebuild. Placeholder `elevenlabs-clone-*` voices were removed.

## Partial, provider-dependent, or not yet fully verified

- Live carrier calls, SMS delivery, inbound SMS, transfer audio, AMD behavior and delivery receipts: Plivo code exists, but no carrier account/number is configured in this workspace. Do not treat these as carrier-tested.
- Voice under one second: not met on this laptop. Measured 24 November 2026 (Apple M4, 16 GB, every model local, memory exhausted): a cold prompt cost 2–67 s on local models, Chatterbox took 28–49 s per sentence. The prompt is now 70% shorter; reaching under 1.5 s needs the cloud parts (OpenRouter or AskG1, Deepgram, ElevenLabs/Cartesia) or a GPU server for the local models.
- Per-call and per-campaign cost: app-side accounting/reporting exists, but carrier-rated cost reconciliation is not verified without carrier usage data.
- Broad advanced contact filtering needs a feature-by-feature UI/API acceptance pass. Sequence analytics: per-step queue and delivery counts are shown for newly queued messages; replies are now attributed per step (an inbound reply is credited to the step of the most recently sent sequenced text to that lead — latest `sent_at`, then `created_at`, then message id — deterministic even when a lead is enrolled in several active sequences), with per-step response rates on the sequences page. Replies with no prior sent sequenced message are unattributed, historical messages lack step attribution, Each sequence also shows outcomes: contacts who replied after enrolling, how many were called afterwards, how many moved to interested / callback requested / won, and how many converted (either). Conversion is counted per lead from their first reply and is not attributed to a specific step.
- Language support: ten interface languages are selectable and about 1,280 of 1,299 page texts are translated across all 51 page routes (see the table). The “140+ pages translated” claim is not met: the app has 51 page routes.
- Payment gateways: adapters and webhook handlers exist, but each gateway still requires production credentials, configured webhook secrets, and live payment verification.
- Browser “WebRTC” calling: the live browser conversation uses the app’s audio/WebSocket path; a carrier-connected WebRTC softphone is not established.
- Plivo and Twilio number search and rental are available in the staff inventory UI (carrier selector), but live purchase and carrier status behaviour are not verified without real Plivo/Twilio credentials. Exotel is unsupported.

## Not implemented in this codebase (or deliberately different)

- Exotel carrier adapter, and Twilio *voice* calling: Twilio is wired for number search/purchase, SIP trunks and health checks only; the voice service and SMS worker still dial and text through Plivo.
- Custom roles beyond the six bundles: the permission matrix edits what each of the six roles may do; a person gets one of those roles.
- Laravel Fortify, Sanctum, and bcrypt specifically: this is a TypeScript/Next.js application with custom auth, and it uses Argon2id for passwords.
- Automatic optimization of campaign send times; current call-time suggestions are historical answer-rate heuristics.

# Provisional latency baseline, 3 Nov 2026

**Provisional:** AskG1 was down (its gateway answered "model g1-chat not found"), so the small local model (Llama 3.2 3B) stood in for the AI's reply. Speech-to-text, text-to-speech and the pipeline are the real ones. **Re-run with AskG1** (`scripts/latency-baseline.sh baseline`) before quoting AI-reply numbers.
Caveats: 7 questions repeat across 20 calls, so some answers came from the answer cache (the LLM stage looks faster than it is); scripted speech, single call at a time; no phone line.

| Stage (p50 / p95) | English | Hindi/Hinglish |
|---|---|---|
| end of speech -> text final (endpoint + STT) | 0.28 s / 1.50 s | **2.08 s** / 2.98 s |
| AI first word (local model, partly cached) | 0.08 s / 7.29 s | 0.19 s / 0.70 s |
| first sentence -> first audio (TTS) | 0.15 s / 0.30 s | **0.93 s** / 2.77 s |
| caller stops -> first sound (often the instant "Sure.") | 0.28 s / 7.64 s | 2.14 s / 5.59 s |
| caller stops -> REAL answer | **1.68 s / 10.32 s** | **3.76 s / 6.12 s** |
| target | < 0.8 s / < 1.2 s | < 0.8 s / < 1.2 s |

Reading it:
- **Hindi speech-to-text is the biggest single cost: 2.1 s.** Sarvam measured 0.26 s on the same kind of audio (docs/stt-comparison-2026-11-03.md).
- **Hindi text-to-speech first sound 0.93 s** (stock Hindi voice + conversion to the staff voice). Sarvam / ElevenLabs / Chatterbox on a GPU avoid the conversion.
- **English speech-to-text is fine** (0.28 s p50); the English miss is the AI's reply, which needs the AskG1 run.
- Neither language is near 0.8 s / 1.2 s today.
